# CRC Card Explanation – Library Lending System

Library lists Book as a collaborator because its responsibilities ("maintain books; add and find books; coordinate borrowing/returning; retrieve books by criteria") cannot be done without asking Book objects for their ISBN, author, and availability and telling them to borrow or return. Book's collaborator list is "None" because its responsibilities ("store book information; maintain availability; validate borrowing/returning; provide book details") involve only its own state, so a Book never needs to know which Library holds it; keeping the dependency one-way keeps Book simple and reusable on its own. The three-book borrowing limit is enforced by Library because it is a rule about the whole collection, and only Library has the "maintain books" and "enforce borrowing limit" responsibilities that let it see how many books are currently borrowed. A single Book only knows whether it is borrowed, not how many others are, so it could not check the limit. Library therefore checks the limit first and then delegates the actual state change to Book, which still validates its own borrow/return transition.
